Why this exists

We were using tools like Graphify to map repos for agents. That works when the consumer is another model. It falls apart when a human needs to understand what just landed — or when PRs get too big to review line by line every day.

The bet: if there is a calm visual way to read code, you can keep up with what agents ship without pretending you read every diff. Underdelta is that map — for people, not just for tools.

Read the code AI writes. Visually.

Philosophy

Capability infrastructure, not a dashboard skin. The browser is the product: a mind map for people who shipped with agents and need to see what is real.

Evidence over invention

Nodes and edges come from the repository. Certainty is marked observed, derived, or inferred. Unknown frameworks stay blank — never hallucinated into a pretty lie.

Product story, not symbol soup

Default view collapses modules and functions into systems, pages, APIs, data, and jobs. The map should answer “what did I build?” before anyone opens Details.

Twin engines

Capability extracts real stacks. Polish keeps the Beginner walk calm. A feature is not done until the map is golden-locked and cold-readable.

What did I actually build?

That is the whole product. Routes, components, databases, migrations, cron, queues, pipelines — linked back to the file and line that justified them.

Not this

Clear refusals keep the map honest.

  • Not a raw call graph or IDE outline wearing new clothes
  • Not AI naming that invents services the code never declared
  • Not a sales funnel — open infrastructure you can run locally
  • Not a dump of tests, fixtures, or build output as “architecture”
