Underdelta

After vibe coding, founders still ask one question. We compile the repo into an evidence-backed map of the product — UI, APIs, data, jobs — with every claim tied to source.

Open on GitHub Try a scan

Philosophy

Underdelta is capability infrastructure, not a dashboard skin. The browser is the product: a mind map for people who shipped with agents and need to see what is real.

Evidence over invention

Nodes and edges come from the repository. Certainty is marked observed, derived, or inferred. Unknown frameworks are left blank — never hallucinated into a pretty lie.

Product story, not symbol soup

Default view collapses modules and functions into systems, pages, APIs, data, and jobs. The map should answer “what did I build?” before anyone opens Details.

Twin engines

Capability extracts real stacks. Polish keeps the Beginner walk calm. A feature is not done until the map is golden-locked and cold-readable.

What did I actually build?

That is the whole product. Routes, components, databases, migrations, cron, queues, pipelines — linked back to the file and line that justified them.

Not this

Clear refusals keep the map honest.

  • Not a raw call graph or IDE outline wearing new clothes
  • Not AI naming that invents services the code never declared
  • Not a sales funnel — open infrastructure you can run locally
  • Not a dump of tests, fixtures, or build output as “architecture”

Try it

Map any project without installing Underdelta into that project. Output lands in .underdelta/ as index.html + architecture.json. 

cd /path/to/your/project
curl -fsSL https://raw.githubusercontent.com/praveen221/underdelta/master/scripts/scan.sh | bash
